## 阶段 1：低风险纯样式

日期：2026-10-18

### 本次范围

按计划实现的第 1 步：斜体、标题分级样式（颜色/粗体/斜体）、代码块 / 行内代码 / 引用块背景。

- **下划线**：用户决定暂时不做，未实现。
- **字体选择**：按计划留到最后单独试，未实现。
- 顺带把 `extension.ts` 从「一个循环里堆正则」改成按职责拆分的三个文件，为后面阶段 2–6 留出结构。

### 代码结构

| 文件 | 职责 |
|---|---|
| `src/extension.ts` | 激活入口：监听事件、重建 decoration 类型、刷新所有可见编辑器 |
| `src/config.ts` | 读取 `mdLivePreview.*` 配置，逐键回退默认值 |
| `src/render.ts` | decoration 类型工厂 + 行级扫描 + 行内标记解析 |

编译产物是 `out/extension.js`、`out/config.js`、`out/render.js`（`tsconfig.json` 的 `rootDir: src` 会保留目录结构）。

### 渲染流程

`renderPreview(editor, types)` 逐行扫描文档，产出 8 个数组，最后一次性 `setDecorations`：

1. **围栏代码块**：`(三个反引号或三个波浪线开头)` 开块，记录围栏字符与长度；只有同字符、长度不短于开块的围栏才关块。块内每一行（含围栏行本身）走 `codeBlock` 整行背景，并 `continue` 跳过后续所有解析 —— 所以代码块里的 `**` 不会被当成粗体。
2. **引用块**：`^\s{0,3}>` 命中即整行加 `quote` 背景。`>>` 嵌套同样命中，不做层级区分。
3. **标题**：`^(#{1,6})([ \t]+)(.*)$`。内容区间加对应级别的 heading decoration；`#` 连同等宽空白进 `hidden`；行尾的闭合井号（`## 标题 ##`）也进 `hidden`，且不参与样式区间。
4. **行内标记**：`scanInline` 解析 `**粗**`、`*斜*`、`***粗斜***`、`_斜_`、`` `代码` ``，内容区间加对应样式，标记符加 `hidden`。

### 行内标记解析（scanInline）

没有用多个正则，而是一次顺序扫描，避免多个正则抢同一段文本（`***x***` 会被 `\*\*` 和 `\*` 同时匹配）。要点：

- **标记符长度**：`***` 优先按粗斜体解析，解析不出来退到粗体、再退到斜体；`**` 先粗体再退斜体。这样 `***a** b*` 这类畸形写法不会整段吞掉。
- **嵌套**：命中外层后递归解析内容区间（上限 4 层），所以 `**粗 *斜* 体**` 能正确出两层。
- **转义**：`\` 直接跳过下一个字符，`\*` 不会起标记。
- **`* 列表项` 不会被当斜体**：开标记符后面必须是内容，不能是空白。
- **`snake_case_name` 不会变斜体**：`_` 不做词内匹配，开标记符前面不能是词字符。
- **flanking 近似**：收标记符左边不能是空白（内容不能以空白结尾）；`_` 的右边不能是词字符。词字符用 `/[\p{L}\p{N}]/u`，中日韩字符也算词字符 —— 所以 `中文_斜体_中文` 按 CommonMark 不生效，要斜体请用 `*`。这一点和 VS Code 内置预览（markdown-it）一致。

### 配置项

`package.json` 新增 `contributes.configuration`：

| 配置 | 类型 | 默认 |
|---|---|---|
| `mdLivePreview.heading` | object，键 `h1`..`h6`，值 `{ color, bold, italic }` | h1–h6 各自配色、均为粗体、非斜体 |
| `mdLivePreview.codeBlock.background` | string（CSS 颜色） | `rgba(128, 128, 128, 0.18)` |
| `mdLivePreview.codeInline.background` | string | `rgba(128, 128, 128, 0.24)` |
| `mdLivePreview.quote.background` | string | `rgba(128, 128, 128, 0.12)` |

`heading` 用**一个 object 配置**而不是 18 个扁平的 `h1.color` / `h1.bold` 键：schema 短得多，且 `src/config.ts` 自己做逐键合并，不依赖 VS Code 对 object 默认值的合并行为。用户只写 `{ "h1": { "color": "#f00" } }` 也能工作。`color` 给空字符串表示不设颜色，只保留字重/字形。

配色默认值取自 Dark+ 的语法高亮色，浅色主题下需要自己改。

### 光标行规则

光标（或选区）覆盖的行 `showSource = true`，这些行不产生 `hidden`，即显示源码；样式仍然照常应用。其余行的标记符被隐藏。

事件监听：`onDidChangeActiveTextEditor`、`onDidChangeVisibleTextEditors`、`onDidChangeTextEditorSelection`、`onDidChangeTextDocument`、`onDidChangeConfiguration`。

相比改之前有两处变化：

- **刷新范围从「当前活动编辑器」改成「所有可见编辑器」**。原来的写法在分屏时会把上一个编辑器的装饰留在原地（那行标记符一直是隐藏的），切回来也不会恢复。
- **配置变化会重建 decoration 类型**。颜色、字重这些属性写在类型上，改不了只能 dispose 旧的再建新的。重建后必须重新 `setDecorations`，否则旧类型建的装饰会随类型一起消失。

### 依赖的非官方能力

隐藏标记符靠 `textDecoration: 'none; display: none;'`。官方 `TextEditorDecorationType` 没有「隐藏文本」的能力，这是往注入的 CSS 里塞声明，属于非官方用法。粗体已在旧版本里验证过可用；**如果某个 VS Code 版本收紧了这段 CSS 的注入，隐藏会失效（标记符不再消失），但样式部分不受影响**。

### 验证方式

1. `npm run compile`（tsc strict）通过，无报错。
2. 用一个打桩的 `vscode` 模块把 `out/render.js` 拉到 Node 里直接跑：stub 提供 `Range`、`window.createTextEditorDecorationType`、`workspace.getConfiguration`，用假 `TextDocument` / `TextEditor` 捕获 `setDecorations` 的入参，逐条核对区间。覆盖的样例：
   - `# 标题` / `## 标题 ##` / `######` 各分级
   - `**粗体**`、`*斜体*`、`***粗斜体***`、`` `行内代码` `` 同行混排
   - `**粗 *斜* 体**` 嵌套
   - `- 列表 *项* 内斜体`（列表标记不误判）
   - `snake_case_name`、`\*转义\*`、`` ```js `` 代码块内的 `**`
   - 光标在标记符所在行时该行不隐藏、其余行仍隐藏
3. 交互效果（字体渲染、背景色是否好看）需要在扩展开发宿主里肉眼确认，stub 测不到。

### 遗留 / 下一步

- **性能**：没有做防抖，每次输入都对整个文档全量重扫。大文件（几千行）可能卡。下一步可以加防抖 + 只扫 `editor.visibleRanges`。
- **光标行粒度**：现在是「整行显示源码」。更细的做法是光标落在标记符区间内才展开那一个标记符，可以留到阶段 2。
- **未实现**：下划线、字体选择、表格/图片/Mermaid 悬停预览、公式渲染。
- **行内代码背景**：`codeInline` 只给内容加背景，没有 `border-radius`，紧贴文字。如果视觉上想更接近内置预览，得再试别的写法。
- **`~` 围栏**：只做了围栏配对，没有额外处理（折叠、缩进代码块同理，缩进的 4 空格代码块目前完全没管）。

## 阶段 1 补充：围栏行隐藏与 [copy] 提示

日期：2026-10-20

### 目标

- 围栏代码块的三个反引号和语言标识（```` ```js ````）不显示，但**保留那一行**（行号也保留）。
- 在代码块左上角显示 `[copy]`；光标进入该行时 `[copy]` 消失、恢复显示原始围栏。

### 实现

新增两个 decoration 类型（`src/render.ts:64`、`src/render.ts:67`）：

| 类型 | 配置 | 作用 |
|---|---|---|
| `fenceHidden` | `textDecoration: 'none; color: transparent !important;'` | 把围栏行文字涂透明，行高保留 |
| `copyHint` | `before.contentText: '[copy]'`，颜色取 `editorCodeLens.foreground`，右边距 `0.8em` | 在行首渲染 `[copy]` |

两者都只加在**围栏行**上（`hideFenceLine`，`src/render.ts:328`）：

- 起始围栏：`fenceHidden` + `copyHint`
- 结束围栏：只加 `fenceHidden`
- 光标（或选区）覆盖的行：两个都不加，直接显示源码

代码块背景 `codeBlock` 仍然覆盖这三行（开围栏、内容、闭围栏），所以隐藏后上下两条空行会带着背景色，看起来就是代码块的内边距。

### 为什么不用 display:none

隐藏粗体标记符用的是 `textDecoration: 'none; display: none;'`，但围栏行不能照抄：

- `before` 的内容和它所在的文本 span 在 DOM 里可能共用或嵌套同一个节点，父节点的 `display: none` 会把 `[copy]` 一起吃掉。
- `color: transparent !important` 只影响文字颜色，不会塌陷布局，`[copy]` 自己带颜色声明，不受继承影响。

代价是围栏文字仍然占宽度（透明），不过它本来就是行内唯一的文字，视觉上看不出差别。

### 行为细节

- 空行是真实存在的：行号继续编号，光标可以停上去。
- 光标停到围栏行时会出现内容"跳一下"（`[copy]` → ```` ```js ````），和粗体标记符的展开规则一致。
- 多个代码块各自在起始围栏显示 `[copy]`。
- 没有加配置开关，行为固定。以后想临时对比源码，可以加 `mdLivePreview.codeBlock.hideFenceLines`。

### 验证

- `npm run compile`（tsc strict）通过。
- 用打桩 `vscode` 的 Node 脚本跑 `out/render.js`，核对 `setDecorations` 入参：
  - 开围栏行：`fenceHidden` + `copyHint` 命中整行；代码行不命中；闭围栏行只命中 `fenceHidden`。
  - 光标在第 0 行 / 代码行 / 围栏行三种情况下，围栏行的处理都符合预期（光标在围栏行时该行两个类型都不出现）。
- **视觉部分（`[copy]` 是否真的画出来、位置是否合适）只能在扩展开发宿主里确认**。如果它被透明或隐藏规则连带影响，备选方案是把 `copyHint` 改挂到零长度 range，或换成 `opacity: 0` 的写法。

### 点击复制：暂未实现

Decoration 没有点击事件，`[copy]` 目前只是视觉提示。后续两条路：

| 方案 | 交互 | 代价 |
|---|---|---|
| CodeLens | 真·单击，点一下复制 | 显示在行的上方，占一条 CodeLens 行；依赖 `editor.codeLens` 开启 |
| Hover + command 链接 | 悬停 `[copy]`，点提示里的链接 | 两次操作，但位置和外观与现在一致 |

复制内容的口径（待定）：围栏之间、不含围栏行；是否保留首尾空行、是否在末尾补换行，需要明确。

## 阶段 1 补充：样式配置化

日期：2026-10-20

### 目标

把样式全部收进 `settings.json`，不再硬编码。可配置对象：

| 配置项 | 可用字段 |
|---|---|
| `mdLivePreview.heading` | 键 `h1`..`h6`，每个包含 `color`、`backgroundColor`、`bold`、`italic` |
| `mdLivePreview.body` | `color`、`bold`、`italic` |
| `mdLivePreview.codeInline` | `color`、`backgroundColor`、`bold`、`italic` |
| `mdLivePreview.codeBlock` | `backgroundColor` |
| `mdLivePreview.quote` | `color`、`backgroundColor` |

示例：

```json
{
  "mdLivePreview.heading": {
    "h1": { "color": "#ff7b72", "backgroundColor": "rgba(255, 123, 114, 0.10)", "bold": true, "italic": false },
    "h2": { "color": "#79c0ff", "backgroundColor": "", "bold": true, "italic": false }
  },
  "mdLivePreview.body": { "color": "", "bold": false, "italic": false },
  "mdLivePreview.codeInline": { "color": "#a5d6ff", "backgroundColor": "rgba(110, 118, 129, 0.30)", "bold": false, "italic": true },
  "mdLivePreview.codeBlock": { "backgroundColor": "rgba(110, 118, 129, 0.15)" },
  "mdLivePreview.quote": { "color": "#8b949e", "backgroundColor": "rgba(110, 118, 129, 0.10)" }
}
```

### 取值约定

- **空字符串 = 不设置**，沿用编辑器主题默认值。不是"继承正文颜色"。
  例如 `heading.h2.color` 留空，h2 用主题色，而不是 `body.color`。
- 只写部分字段也安全：`{ "h1": { "color": "#f00" } }` 其余字段走默认值。
- 类型不符（比如把 `bold` 写成字符串）会被忽略并回退默认值。

### 实现要点

**1. 配置结构**

`src/config.ts` 里所有样式统一成 `TextStyle { color, backgroundColor, bold, italic }`，用 `readStyle` 做逐字段合并。`codeBlock` 只读 `backgroundColor`，`quote` 只读 `color` / `backgroundColor`。

**2. 标题 / 引用 / 代码块用整行装饰**

这三类都设 `isWholeLine: true`：背景色铺满整行，标题看起来是一条色带，引用和代码块的背景也不会断在文字末尾。

**3. 正文要避开其它区域**

正文不能直接铺满全文，否则会和标题、行内代码、引用、代码块抢颜色。做法是**区间相减**（`bodyRanges`，`src/render.ts`）：

- 标题行、引用行、围栏行、代码块内容行：整行记为已占用
- 行内标记（含隐藏的标记符）：`[openStart, closeEnd]` 记为已占用
- 用整行减去这些区间，得到互不重叠的正文区间

这样就不依赖 decoration 之间的优先级，结果可预测。正文样式未配置时（`color` 为空且 `bold`/`italic` 都是 `false`）完全不生成区间，默认零开销。

**4. 代码块 / 引用不碰字重和字形**

`styleOptions(style, wholeLine, font)` 的 `font` 参数对 `codeBlock` 和 `quote` 传 `false`，否则整行装饰里的 `fontWeight: normal` 会把块内 `**粗体**` 覆盖掉。

### 破坏性变更

上一版的三条扁平配置已改名，旧的 `background` 键不再生效：

| 旧键 | 新键 |
|---|---|
| `mdLivePreview.codeBlock.background` | `mdLivePreview.codeBlock.backgroundColor` |
| `mdLivePreview.codeInline.background` | `mdLivePreview.codeInline.backgroundColor` |
| `mdLivePreview.quote.background` | `mdLivePreview.quote.backgroundColor` |

`mdLivePreview.heading` 结构不变，只是每个级别多了 `backgroundColor`。

### 验证

- `npm run compile`（tsc strict）通过。
- 打桩 `vscode` + 自定义配置跑 `out/render.js`，确认：
  - 五类样式各自生成独立的 decoration 类型，选项正确（整行、颜色、背景、字重、字形）。
  - 正文区间正确避开标题行、引用行、代码块行；行内标记处被切开，例如 ``正文 **粗体** 和 `代码` 还有文字。`` 得到三段正文区间。
  - 光标行规则、围栏隐藏、`[copy]` 均未受影响。
- 视觉效果（色带宽度、配色观感）仍需在扩展开发宿主里确认。

## 修复记录：代码块内容被隐藏

日期：2026-10-20

- **现象**：开启围栏隐藏后，代码块里的代码内容也一起不可见了。
- **原因**：`renderPreview` 里 `if (fence)` 这个分支在围栏打开期间**每一行**都会进入，之前无条件调用了 `hideFenceLine`，于是块内所有代码行都被涂成透明。实际只有**闭合围栏**那一行需要隐藏。
- **修复**：先算出 `closes`，只有闭合围栏才调用 `hideFenceLine`；块内其余行只加 `codeBlock` 背景，不碰文字。
- **回归验证**：打桩脚本改为带断言的版本，覆盖以下条件：
  - `fenceHidden` 只命中开围栏和闭围栏两行（样例中为第 4、9 行）；
  - 代码内容行命中 `fenceHidden` 的数量为 0；
  - `copyHint` 只命中开围栏；
  - `codeBlock` 仍覆盖整个代码块，包括围栏行。

教训：之前的验证脚本只打印区间、没有断言，误把 `[5:0-12]`（代码内容行）看成了正常输出。这次改成显式 PASS/FAIL 断言。

## 阶段 3：标题层级徽章（L1 之类）

日期：2026-10-20

### 需求

标题行首显示一个层级标记（默认 L1..L6），用来在纯文本编辑器里一眼看出当前行是几级标题。

### 实现

VS Code 的 before.contentText 可以在装饰区间的起点插入一段并不存在的文本（和 [copy] 同一个机制）。因为 contentText 写在 decoration 类型上、不能按行变化，所以按 6 个层级各建一个类型：types.headingPrefix[0..5]，内容分别是 L1..L6。

- 配置：mdLivePreview.headingPrefix，字段 enabled / format / color / backgroundColor。format 是模板，{level} 替换成 1..6，所以想显示 H1 、H1： 都只改这一个字符串。空串或不写退回默认的 L{level}。
- 徽章加在标题内容区间（不是整行），起点正好是 # 后面的第一个字符，所以徽章紧贴正文最前面。
- 光标行不画徽章：那一行 # 是显示出来的（沿用既有「光标行显示源码」规则），再插一个徽章会和 # 抢行首、看起来像乱码。
- before 的 backgroundColor 会连同左右 margin 一起涂色，视觉上就是一个小胶囊；不想要底色把它设成空串即可。
- 代码块围栏内不解析标题（沿用既有 continue），所以 js 围栏里的 # 注释 不会长徽章。

### 顺带回答的问题：一行里能不能混多种样式

可以，而且现在的代码就是这么做的。decoration 的样式区间是任意子区间，互不重叠即可 —— 一行里 正文、粗体、行内代码 会同时命中 body、bold、codeInline 三种类型。两个约束：

- color / 字重 / 字形冲突时，后 setDecorations 的类型赢，所以代码里用 occupied 区间先把正文样式切开，保证同一字符只被一种样式覆盖（见 bodyRanges）。
- 但 before / after 只能加在区间边界上，且同一位置只有一个装饰能插入内容，所以一行里如果多个装饰都往同一个位置插内容会互相覆盖 —— 这也是徽章按 6 个类型分开、且和 [copy]（只在围栏行）天然不冲突的原因。

### 验证

npm run compile（tsc strict）通过；打桩 vscode 跑 out/render.js 断言：6 个徽章类型内容为 L1..L6、color 空时不写进 before、徽章区间与标题内容区间一致、光标行不产生徽章、围栏内 # 不产徽章、enabled false 时不建类型但标题样式照常、disposeDecorationTypes 会释放徽章类型。全部 PASS。

## 修复记录：行内代码样式被整行背景盖掉

日期：2026-10-20

- **现象**：把 codeInline 配成白字 + 深灰底 + 粗体，感觉「没生效」。
- **定位**：打桩 vscode 跑 out/render.js 确认 codeInline 的区间和 options 都对，纯正文行里完全生效；吃亏的是引用块 / 代码块里的行内代码。

## 修复记录：decoration 的 color 被语法高亮吃掉 + 默认值改不动

## 阶段 6：通用样式成员 underline / border 开关

日期：2026-10-21

- TextStyle 再加两个可选布尔：underline、border。所有样式对象（六级标题 / 正文 / 行内代码 / 代码块 / 引用块）都能用。默认全关，package.json 只更新了各段 markdownDescription，default 不变。
- **underline 走 textDecoration 注入通道**：官方 decoration 没有下划线属性，而 textDecoration 会原样注入 CSS。和 color 的 !important 注入合并成一条声明：有颜色时开头补 none;（原有语义），开了下划线改成 underline。例：underline+color = `underline; color: X !important;`。

- border:false 可以强制关掉引用块的竖条（即使 borderColor 有值），这是布尔开关优先于 borderColor 的直接推论。
- 注意：整圈边框给整行装饰（标题等）时上下边框会让每行高约 +2px，标题是单行装饰问题不大；多行块（codeBlock）想开整框建议把 borderWidth 调成只留左右，如 `0 0 0 4px`。
- 验证：tsc strict 通过；打桩断言全 PASS：默认无 underline/border 输出、h1 开关后 textDecoration 正确合并、border 默认色、border:false 关掉引用竖条、body 纯下划线、自定义 border* 三件套透传、渲染区间不受影响。
