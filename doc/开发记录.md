- **下划线**：用户决定暂时不做，未实现。
- **字体选择**：按计划留到最后单独试，未实现。
- 顺带把 `extension.ts` 从「一个循环里堆正则」改成按职责拆分的三个文件，为后面阶段 2–6 留出结构。

### 代码结构

| 文件 | 职责 |
|---|---|
| `src/extension.ts` | 激活入口：监听事件、重建 decoration 类型、刷新所有可见编辑器 |
| `src/config.ts` | 读取 `mdLivePreview.*` 配置，逐键回退默认值 |
| `src/render.ts` | decoration 类型工厂 + 行级扫描 + 行内标记解析 |

编译产物是 `out/extension.js`、`out/config.js`、`out/render.js`（`tsconfig.json` 的 `rootDir: src` 会保留目录结构）。

### 渲染流程

`renderPreview(editor, types)` 逐行扫描文档，产出 8 个数组，最后一次性 `setDecorations`：

1. **围栏代码块**：`(三个反引号或三个波浪线开头)` 开块，记录围栏字符与长度；只有同字符、长度不短于开块的围栏才关块。块内每一行（含围栏行本身）走 `codeBlock` 整行背景，并 `continue` 跳过后续所有解析 —— 所以代码块里的 `**` 不会被当成粗体。
2. **引用块**：`^\s{0,3}>` 命中即整行加 `quote` 背景。`>>` 嵌套同样命中，不做层级区分。
3. **标题**：`^(#{1,6})([ \t]+)(.*)$`。内容区间加对应级别的 heading decoration；`#` 连同等宽空白进 `hidden`；行尾的闭合井号（`## 标题 ##`）也进 `hidden`，且不参与样式区间。
4. **行内标记**：`scanInline` 解析 `**粗**`、`*斜*`、`***粗斜***`、`_斜_`、`` `代码` ``，内容区间加对应样式，标记符加 `hidden`。

### 行内标记解析（scanInline）

没有用多个正则，而是一次顺序扫描，避免多个正则抢同一段文本（`***x***` 会被 `\*\*` 和 `\*` 同时匹配）。要点：

- **标记符长度**：`***` 优先按粗斜体解析，解析不出来退到粗体、再退到斜体；`**` 先粗体再退斜体。这样 `***a** b*` 这类畸形写法不会整段吞掉。
- **嵌套**：命中外层后递归解析内容区间（上限 4 层），所以 `**粗 *斜* 体**` 能正确出两层。
- **转义**：`\` 直接跳过下一个字符，`\*` 不会起标记。
- **`* 列表项` 不会被当斜体**：开标记符后面必须是内容，不能是空白。
- **`snake_case_name` 不会变斜体**：`_` 不做词内匹配，开标记符前面不能是词字符。
- **flanking 近似**：收标记符左边不能是空白（内容不能以空白结尾）；`_` 的右边不能是词字符。词字符用 `/[\p{L}\p{N}]/u`，中日韩字符也算词字符 —— 所以 `中文_斜体_中文` 按 CommonMark 不生效，要斜体请用 `*`。这一点和 VS Code 内置预览（markdown-it）一致。

### 配置项

`package.json` 新增 `contributes.configuration`：

| 配置 | 类型 | 默认 |
|---|---|---|
| `mdLivePreview.heading` | object，键 `h1`..`h6`，值 `{ color, bold, italic }` | h1–h6 各自配色、均为粗体、非斜体 |
| `mdLivePreview.codeBlock.background` | string（CSS 颜色） | `rgba(128, 128, 128, 0.18)` |
| `mdLivePreview.codeInline.background` | string | `rgba(128, 128, 128, 0.24)` |
| `mdLivePreview.quote.background` | string | `rgba(128, 128, 128, 0.12)` |

`heading` 用**一个 object 配置**而不是 18 个扁平的 `h1.color` / `h1.bold` 键：schema 短得多，且 `src/config.ts` 自己做逐键合并，不依赖 VS Code 对 object 默认值的合并行为。用户只写 `{ "h1": { "color": "#f00" } }` 也能工作。`color` 给空字符串表示不设颜色，只保留字重/字形。

配色默认值取自 Dark+ 的语法高亮色，浅色主题下需要自己改。

### 光标行规则

光标（或选区）覆盖的行 `showSource = true`，这些行不产生 `hidden`，即显示源码；样式仍然照常应用。其余行的标记符被隐藏。

事件监听：`onDidChangeActiveTextEditor`、`onDidChangeVisibleTextEditors`、`onDidChangeTextEditorSelection`、`onDidChangeTextDocument`、`onDidChangeConfiguration`。

相比改之前有两处变化：

- **刷新范围从「当前活动编辑器」改成「所有可见编辑器」**。原来的写法在分屏时会把上一个编辑器的装饰留在原地（那行标记符一直是隐藏的），切回来也不会恢复。
- **配置变化会重建 decoration 类型**。颜色、字重这些属性写在类型上，改不了只能 dispose 旧的再建新的。重建后必须重新 `setDecorations`，否则旧类型建的装饰会随类型一起消失。

### 依赖的非官方能力

隐藏标记符靠 `textDecoration: 'none; display: none;'`。官方 `TextEditorDecorationType` 没有「隐藏文本」的能力，这是往注入的 CSS 里塞声明，属于非官方用法。粗体已在旧版本里验证过可用；**如果某个 VS Code 版本收紧了这段 CSS 的注入，隐藏会失效（标记符不再消失），但样式部分不受影响**。

   - `- 列表 *项* 内斜体`（列表标记不误判）
   - `snake_case_name`、`\*转义\*`、`` ```js `` 代码块内的 `**`

### 遗留 / 下一步

- **性能**：没有做防抖，每次输入都对整个文档全量重扫。大文件（几千行）可能卡。下一步可以加防抖 + 只扫 `editor.visibleRanges`。
- **光标行粒度**：现在是「整行显示源码」。更细的做法是光标落在标记符区间内才展开那一个标记符，可以留到阶段 2。
- **未实现**：下划线、字体选择、表格/图片/Mermaid 悬停预览、公式渲染。
- **行内代码背景**：`codeInline` 只给内容加背景，没有 `border-radius`，紧贴文字。如果视觉上想更接近内置预览，得再试别的写法。
- **`~` 围栏**：只做了围栏配对，没有额外处理（折叠、缩进代码块同理，缩进的 4 空格代码块目前完全没管）。
